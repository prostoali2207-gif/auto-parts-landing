## P1 — Typography hierarchy and apparent size
The hero typography is the strongest part of V6. Do not replace it merely for novelty. The primary weakness appears below the hero: process copy, evidence metadata, form labels/helper text and desktop control typography become visually undersized relative to the page scale.

### Required correction
- Keep the existing display family unless side-by-side render testing proves a clear gain from another face. Do not add a font dependency just to make the page feel new.
- Hero headline remains the typographic anchor. Preserve its authored line breaks and tight display leading.
- Desktop body/support copy: target apparent size around 16–18px with comfortable leading and bounded measure.
- Mobile important body/helper copy: minimum apparent size around 15–16px. Do not let explanatory text read like legal fine print.
- Form labels: raise visual presence; use roughly 12–13px minimum where uppercase/mono is used, with restrained tracking. Do not make every field label mono.
- Form entered text/placeholders: around 15–16px apparent size; VIN/OEM may use mono only where it improves scanning.
- Group headings (`Автомобиль`, `Деталь`, `Контакт`) need stronger contrast from labels: approximately 26–34px desktop and 24–30px mobile depending on final render.
- Small metadata such as `REQUEST A PART`, `VEHICLE`, `PART`, `CONTACT` must remain secondary but readable; never use tiny gray text as the source of sophistication.
- Tighten the relationship between heading, helper, label and control so proximity creates hierarchy instead of relying on tiny type.

### Typography acceptance
At a normal viewing distance, a squint test should reveal: promise → CTA → section heading → group heading → fields. No important request instruction should require close inspection.

## P1 — Hero CTA must compete with the hero, not disappear beneath it
The first CTA is understandable but visually too small relative to the monumental headline and package object.

### Required correction
- Keep one primary hero CTA only.
- Increase its visual mass: practical target height 56–60px desktop and 54–58px mobile; label around 16–18px apparent size.
- Keep the hard-edge physical button language. The current hard shadow/press behavior can stay if it remains controlled.
- Attach the CTA more clearly to the orange route so it reads as the action generated by the composition, not a generic button placed below copy.
- Supporting microcopy must not compete with or visually weaken the CTA. Keep it close but quieter and readable.
- Header CTA remains deliberately secondary to the hero CTA.

### CTA acceptance
When the viewport is blurred/squinted, both the commercial promise and the primary action must remain obvious.

## P1 — Desktop process composition needs tighter Gestalt
The current 01 / 02 / 03 idea is correct, but numbers, copy and route feel partially independent. The section has too much unused vertical space for the amount of information.

### Required correction
- Do not create cards.
- Keep one wide composition with the three serial numerals.
- Pull each step's copy visibly closer to its corresponding numeral and route intersection so proximity communicates grouping.
- Treat the orange line as a real continuity path through the three beats; avoid it feeling like an unrelated stripe placed between numbers and copy.
- Reduce dead vertical space by roughly 15–25% after render testing, without compressing the section into a conventional three-column feature row.
- Preserve asymmetry: `01`, `02`, `03` may sit at different vertical positions, but every displacement must have a visible compositional reason.
- Mobile remains three typographic beats, not boxes. Keep the alternating edge rhythm but ensure the route and copy clearly belong to each step.

## P1 — Evidence gap is currently too empty and disconnected
The calm section after process is useful, but the current desktop render reads as unused space rather than deliberate release.

### Required correction
- Keep the same message and no new claims.
- Reduce section height/empty area approximately 20–30% unless a stronger material composition earns the space.
- Bring the small `VIN / OEM / PHOTO / DESCRIPTION` vocabulary and the main statement into a stronger editorial relationship.
- Use one subtle package/label material cue or continuation of the routing geometry only if it helps bridge into the request chapter.
- Do not add cards, icons, testimonials, badges or decorative automotive imagery.

## P1 — Request transition must feel like opening the package
The black `Что нужно найти?` chapter is strong in isolation, especially on mobile, but desktop currently reads like a separate poster inserted above an otherwise generic form.

### Required correction
- Keep the black chapter and orange edge/route.
- Make its geometry visibly continue into the request surface: an angled/cut lower edge, route crossing, or shared alignment must create one `opened package → work surface` event.
- Reduce the sense of a floating black rectangle inside a large neutral void.
- The `01` serial in the request intro may remain large, but it must support the transition rather than compete with `Что нужно найти?`.
- Desktop transition should be more integrated; mobile transition is already close to the target and should not be overworked.

## P1 — Request form must look designed at the same level as the hero
This is the biggest perceived-quality gap. The form is usable, but desktop falls back toward a plain form/document aesthetic after a strongly authored first half.

### Required correction
Preserve the existing single-page form and all field semantics. Do not create a wizard.

#### Desktop structure
- Use one broad manifest/work-surface composition with a clear underlying grid.
- Keep three groups: vehicle, part, contact.
- Group by hierarchy, whitespace and thin rules rather than cards.
- Keep a left contextual column only if it earns its width. If used, target a stable contextual rail around 200–260px and a main control column around 700–820px within a max content width around 1080–1180px.
- Reduce the current excessive vertical gaps between groups. Target roughly 64–80px major-group separation, tuned by render, rather than large empty bands.
- Make labels/helpers readable enough that the form does not look like tiny annotation around oversized whitespace.
- Control heights should feel deliberate and tactile, generally around 48–54px for single-line inputs.
- Photo upload remains the most tactile secondary control. Keep it generous, but avoid making it a card-within-a-card.
- Thin separators should align across the work surface and reinforce the manifest idea.

#### Mobile structure
- Keep single-column fields and persistent labels.
- Increase helper/label readability.
- Preserve generous tap targets and clear field boundaries.
- Do not add decorative elements inside the active field flow.
- Keep the photo control easy to tap and filename/error states able to wrap.

- Mobile submit should be full available width and around 54–58px high.
- Keep only one dominant submit CTA in the form viewport.

## P2 — Packaging object should read as art direction, not fake logistics proof
The package label is successful as a visual object, but the barcode-like block can look more documentary than expressive.

### Required correction

- Make any barcode/routing mark clearly non-scannable and non-factual: irregular graphic ticks, segmented blocks, or an abstract identification rhythm with no plausible tracking number.
- No fabricated order ID, shipment status, inventory count or supplier evidence.
