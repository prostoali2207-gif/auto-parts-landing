# Spline V7 — Narrow Visual Refinement

Status: `VISUAL TASTE: READY FOR FRONTEND`

## Scope
This is not a new reset. Preserve V7 EXPLODED OBJECT hero, palette, typography, request logic, analytics and CRM contract. Refine only the weak rendered areas identified on the real ~390px production screenshots: process, acid evidence chapter, request transition/form, and supporting-text legibility.

## Render findings driving the refinement

### P1 — Process coherence / mobile rhythm
The rendered 01 / 02 / 03 steps read as three different visual treatments and consume too much vertical travel. The V7 contract requires one editorial composition with continuity through alignment, spacing and restrained connector logic.

Refinement contract:
- one numeral treatment across all three steps;
- one text alignment grammar across all steps;
- cobalt is continuity, not a separate style for one step;
- mobile becomes a compact staggered sequence with controlled overlap/offset, not three isolated poster events;
- preserve concise Vehicle / Part / Contact copy.

### P1 — Evidence statement readability
The current acid chapter combines headline and explanation into one oversized paragraph, causing excessive word-by-word wrapping on phone.

Refinement contract:
- keep the full-width signal-acid chapter;
- separate the approved key truth into a display heading: `Не нужно знать точное название детали.`;
- render `Фото, OEM-номер или описание помогут менеджеру начать подбор.` as supporting copy with comfortable measure and leading;
- keep acid as the loud chapter field without making all text equally loud.

### P1 — Form perceived-quality continuity
The request flow is functionally correct but the mobile render falls back to generic form styling after the expressive request intro. V7 requires a calm interior, not a visually unrelated default form.

Refinement contract:
- keep one broad cold-white surface and no nested cards;
- strengthen each group as an editorial row using number + heading + aligned rule, not boxes;
- maintain conventional labels and native inputs;
- increase control finish through value, border, focus and spacing rather than decoration;
- create a restrained cobalt structural spine/rule that visually relates the three groups without becoming CRM/workstation chrome;
- keep acid only for submit and file action;
- reduce unnecessary vertical travel on phone while preserving comfortable targets and error/helper adjacency.

### P2 — Supporting copy legibility
Increase apparent size/contrast of helper text and supporting copy where the current real-phone render is too faint.
