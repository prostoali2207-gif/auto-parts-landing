# Интеграция лендинга с BayerCRM

## Цель

Лендинг не должен напрямую писать в таблицы Supabase. Основная форма `Найти запчасть` отправляет запрос в один публичный Edge Function, который создаёт обычную заявку BayerCRM.

Путь:

`Лендинг -> Edge Function -> requests + request_items + request-photos -> менеджер в BayerCRM`

## Контракт V1

### Обязательное

- `contact` — телефон / WhatsApp / Telegram;
- минимум один способ определить автомобиль:
  - VIN, **или**
  - марка + модель + год;
- минимум одна деталь;
- у каждой детали должен быть хотя бы один сигнал: название, OEM/Part Number, описание или фото.

### Необязательное

- имя клиента;
- VIN, если указаны марка/модель/год;
- точное название детали, если есть фото/номер/описание;
- OEM/Part Number;
- описание;
- фотографии.

## Формат запроса

`multipart/form-data`

Поля:

- `contact`: string
- `clientName`: string, optional
- `vin`: string, optional
- `carMake`: string, optional
- `carModel`: string, optional
- `carYear`: string, optional
- `website`: honeypot, must be empty
- `parts`: JSON array

Пример `parts`:

```json
[
  {
    "partName": "Передняя фара",
    "partNumber": "",
    "description": "Правая сторона",
    "photoKeys": ["part-0-photo-0"]
  }
]
```

Фотографии передаются в том же `FormData` под ключами из `photoKeys`.

## Ответ

Успех:

```json
{
  "ok": true,
  "requestId": "uuid",
  "requestNumber": 123
}
```

Ошибка:

```json
{
  "ok": false,
  "error": "Короткое безопасное сообщение"
}
```

## Безопасность

- service-role key существует только внутри Edge Function;
- лендинг не получает прямой доступ к `requests`, `request_items` или Storage write;
- продавец определяется серверной переменной окружения, а не значением из браузера;
- разрешённые origins задаются серверной переменной;
- honeypot против простых ботов;
- ограничить количество и размер фотографий;
- разрешить только изображения;
- не возвращать клиенту внутренние данные профиля/CRM.

## Важная проверка перед реализацией упрощённой формы

Текущая публичная форма BayerCRM требует имя, марку, модель, год и название детали. Перед тем как разрешить `VIN + фото + контакт` без остальных полей, нужно проверить live-схему BayerCRM: nullable/constraints для `requests.client_name`, `car_make`, `car_model`, `car_year` и `request_items.part_name`.

Если эти поля сейчас `NOT NULL`, сначала нужна безопасная миграция либо отдельный серверный нормализатор. Не записывать выдуманные марку/модель/деталь только ради обхода ограничений.

## UX лендинга

Пользователь не должен видеть техническую структуру CRM. Форма остаётся короткой:

1. Автомобиль — VIN **или** марка/модель/год.
2. Деталь — фото / название / OEM / короткое описание.
3. Контакт.
4. `Отправить заявку`.

После успеха показать номер заявки и понятное сообщение, что менеджер свяжется с клиентом. Не обещать конкретное время ответа, пока бизнес его не подтвердил.
