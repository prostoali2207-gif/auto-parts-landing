# Spline — Application Language

Status: proposed V1 brand application contract.

## Purpose
Turn the approved Spline identity into a repeatable system for real business touchpoints without inventing a second aesthetic for every channel.

The rule is simple:

**information first, brand recognition second, decoration last.**

Spline should look like one business whether the customer sees an Instagram post, a request sheet, a quote, a parts label or a small avatar.

## Evidence translated into principles

### Structured labels
GS1 logistics guidance separates human-readable text, supporting information and machine-readable data into clear functional blocks. Spline should borrow the hierarchy principle, not GS1 compliance claims: identifiers need visible data titles, machine-readable areas need clean quiet space, and decorative graphics must not interfere with scanning or interpretation.

### Unified system
IBM Design Language frames brand systems as common, reusable rules across communications and digital experiences. Spline should likewise reuse a small set of recognizable devices instead of inventing channel-specific styles.

## Core application grammar

Every branded application should be built from only these elements:
- approved A1.1 SPLINE wordmark;
- compact plain `S` only when the full wordmark physically cannot fit;
- Spline Ink / Paper / Surface neutrals;
- Signal orange as one high-signal accent;
- IBM Plex Sans for communication;
- IBM Plex Mono for VIN, OEM, part numbers, request IDs and technical metadata;
- thin rules, short alignment ticks, open frames and structured data blocks;
- real part / packaging / label photography where credible assets exist.

Do not add a new badge, shield, icon family, texture, gradient, metallic effect or racing motif for individual applications.

## 1. Social / Instagram / Telegram

### Primary social template
Use for normal feed posts and share graphics.

Structure:
1. wordmark in a quiet corner;
2. one real image or one strong text statement;
3. short headline;
4. optional technical identifier such as `OEM / PART NO.` or vehicle reference;
5. one small Signal orange cue maximum.

Rules:
- image or message must dominate, not the logo;
- no repeated sticker/badge collections;
- no fake pricing, stock, delivery or fitment claims;
- no generic supercars as filler;
- avoid automotive-poster aesthetics, speed lines and dark red/black tuning layouts;
- if there is no credible image, use a clean typography-led post rather than stock filler.

### Technical social post
Use when the content itself is identification-driven: VIN, OEM, part-number explanation, sourcing process or fitment clarification.

Structure:
- large useful identifier or short statement;
- Mono metadata line;
- one diagrammatic rule/index cue only if it explains structure;
- wordmark secondary.

### Avatar
Use the approved compact plain `S` asset only where the full wordmark cannot fit. Do not build a circular badge around it. Background may be Spline Ink, Paper or Signal depending on context, provided the S remains high-contrast.

## 2. Quotes / request sheets / business documents

The document should read like operational information, not advertising collateral.

Recommended hierarchy:
1. wordmark top-left;
2. document type top-right or below brand;
3. visible request / quote / reference number;
4. customer / vehicle / part blocks;
5. commercial or status information only when verified;
6. footer/contact details.

Rules:
- use Mono for VIN, OEM, request IDs and machine-like values;
- use Sans for names, instructions and commercial text;
- use thin rules and spacing instead of large decorative panels;
- Signal orange may mark one status/reference point, not entire sections;
- never make unverified guarantees visually prominent;
- do not use watermark patterns, chrome effects or decorative vehicle silhouettes.

## 3. Part labels / stickers

This is an identification surface first.

Recommended information order:
1. SPLINE wordmark or compact S if space-constrained;
2. part name / short descriptor;
3. OEM / PART NO.;
4. vehicle / fitment reference only if verified;
5. request / internal reference;
6. optional barcode / QR only when a real operational workflow requires it.

Rules:
- black/dark print on a light field is the default for maximum legibility;
- preserve clear blank space around any barcode / QR; never place decorative marks inside its quiet area;
- show human-readable identifier text near machine-readable codes;
- keep technical data larger than decorative branding when space is tight;
- avoid full-bleed orange labels unless there is a real operational reason;
- never imply OEM/manufacturer affiliation through copied visual language.

### Small sticker hierarchy
When space is extremely limited:
`S` -> `OEM / PART NO.` -> request/reference.

The customer or staff should be able to identify the part faster than they identify the brand.

## 4. Packaging

No full packaging system is justified for V1.

If generic cartons/bags need Spline identification, use a simple one- or two-color label/stamp using the part-label rules above. Do not spend design effort on custom boxes, tape patterns or elaborate unboxing until the business has a real packaging requirement.

## 5. Photography treatment across applications

Preferred:
- real parts;
- OEM labels and packaging where safe;
- connectors, mounting surfaces, housings, teeth, seals and fasteners;
- part-in-hand / inspection moments;
- real shelves, receiving or sourcing context when available.

Treatment:
- neutral believable color;
- tight useful crop;
- hard rectangular edges;
- no fake cinematic grade;
- no AI-generated warehouse/inventory presented as real.

## 6. Repetition rule

A Spline application is recognizable through repetition of the system, not repetition of the logo.

Do not place the wordmark multiple times on one small composition. Recognition should come from:
- typography;
- data hierarchy;
- Paper/Ink foundation;
- restrained orange signal;
- technical identifiers;
- real automotive evidence.

## 7. Acceptance test

Before approving any new brand application ask:
1. Is the useful information immediately clear?
2. Is the identity recognizably Spline without a decorative automotive cliché?
3. Is Signal orange functioning as a signal rather than wallpaper?
4. Are technical identifiers treated consistently?
5. Is every business claim verified?
6. Would the layout still work in monochrome?
7. If a barcode/QR exists, is its clear area protected?
8. Did we add anything purely to make it look more designed?

If #8 is yes, remove it unless it has a specific communication function.

## V1 decision
This contract is enough for current social posts, document layouts and operational labels. Do not create a broader packaging or merchandise identity until a concrete business need appears.
